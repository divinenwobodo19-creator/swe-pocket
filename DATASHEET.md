# Datasheet — SWE-Pocket

**Release:** SWE-Pocket v1.0 (size-stratified evaluation resource)
**Built for:** Gemma 4 Developer Agent Paper Track (Best New Resource)
**Date:** October 2026 · **Maintainer:** N-Library (Divine Nwobodo)
**Related docs:** `paper/swe-pocket.md`, `resources/provenance_findings.md`, `README.md`

This datasheet documents the resource's composition, construction, and limits.
"We do not know" is stated where true.

---

## 1. Motivation

- **Goal:** provide a Python coding-agent evaluation resource that reports
  *repository size* as a measured variable, which standard SWE benchmarks fix by
  construction. Built so that agents on consumer hardware can be evaluated on a
  resource whose structure decomposes into interpretable axes.
- **Creator:** N-Library. The resource combines competition-provided material
  (referenced, not redistributed) with tasks we mined from public repositories.
- **Funding:** self-funded; no external grant.

## 2. Composition

- **Each instance** is a single-repository software task: a problem statement, a
  gold patch (the maintainer's merged fix), and a test patch (the tests that
  distinguish fixed from unfixed), keyed to a `base_commit` and its code graph.
- **Total instances:** **153** across two strata:
  | stratum | tasks | repos | nodes | source |
  |---|---|---|---|---|
  | large | 129 | `fastapi` 67, `rich` 48, `requests` 13, `httpx` 1 | 711–4,597 | provided `tasks.jsonl` |
  | compact | 24 | `packaging`, `prettytable`, `parso`, `python-dotenv` (6 each) | 75–606 | mined by us |
- **What is not included:** no model predictions, no agent trajectories, no
  baseline resolve rates. Model baselines were deliberately out of scope
  (see paper §5).
- **Coverage:** Python only. No non-Python languages, no compiled-language call
  semantics.
- **Skew:** the large stratum is dominated by `fastapi` (67/129) and `rich`
  (48/129); the compact stratum is balanced (6/24 each). `httpx` contributes one
  task and is not representative.

## 3. Collection process

- **Large stratum:** taken directly from the competition's `tasks.jsonl`. Every
  `instance_id` was verified to correspond to a **merged upstream pull request**,
  and every `base_commit` to equal that PR's base SHA (129/129, via the GitHub
  API). Full method and evidence in `resources/provenance_findings.md`.
- **Compact stratum:** `scripts/mine_compact.py` queries each seed repository's
  merged pull requests and keeps those touching ≤6 files and 4–160 lines with
  both a source change and a test change, targeting 6 per repository. This is an
  **automated filter with a sampling bias toward small, self-contained fixes**;
  larger multi-file fixes were excluded by design.
- **Rights/consent:** all source material is public open-source code under the
  upstream projects' own licences. We preserve attribution to each upstream PR in
  every task record. No personal or user data is collected.

## 4. Preprocessing / cleaning / labelling

- Provided `tasks.jsonl` fields are used as-is. We split each `patch` into
  source vs test files with a path heuristic (`tests/`, `test_*.py`, `conftest.py`).
- Compact graphs are generated by parsing each repository at `base_commit` with
  Python's `ast` (`scripts/build_compact_graphs.py`), emitting node ids
  `module.symbol` and `calls` edges (only uniquely resolved bare-name calls) to
  match the provided graph schema.
- FAIL_TO_PASS / PASS_TO_PASS test names are extracted from provided `test_patch`
  diffs by heuristic (`scripts/extract_tests.py`); see §8 for the error mode.
- Originals are retained; no upstream code is modified.

## 5. Uses

- **Intended for:** research on repository-scale effects in coding agents;
  structural benchmarking; building navigation-aware agent scaffolds.
- **Not suitable for:** claims about agent accuracy (see §8), high-stakes
  code-modification decisions, or any use implying the resource measures
  correctness of fixes rather than their structure.
- **Misleading if used otherwise:** the structural metrics are a *proxy* for
  navigation cost, not a measurement of difficulty. Reporting them as difficulty
  would overstate what was measured.

## 6. Distribution

- **Provided graphs/embeddings are NOT redistributed** — only metrics derived
  from them are reported. They remain under the competition's terms.
- **Our artifacts** (mined tasks, generated graphs, tooling, derived metric
  tables) are released under CC-BY-4.0 (data) and MIT (code), with attribution
  preserved; upstream code inside compact task patches keeps its own licence
  (see `LICENSE-DATA`).
- **Who can use it:** anyone; no access restriction on our artifacts.

## 7. Maintenance

- Maintained by N-Library. Corrections via the project issue channel
  (GitHub issues on this repository).
- **Versioning:** semantic; v1.0 is this frozen submission. Upstream PRs may be
  force-pushed or removed; mined tasks cite `base_commit` so provenance is
  re-checkable but not guaranteed permanent.
- **Withdrawal:** a task is withdrawn if its upstream PR is retracted or its
  licence changes; withdrawals are recorded in version history.

## 8. Known limitations & guarantees

- **We do NOT guarantee agent accuracy of any kind.** No model was run.
- **Provenance verified** for the large stratum (129/129 merged PRs) at build
  time; not re-verified continuously.
- **FAIL_TO_PASS extraction is a heuristic lower bound:** names come from *added*
  test functions. Tasks that only *modify* existing tests are caught by churn,
  not by name. Exact test names require a real pytest run against the snapshots,
  which is out of scope for v1.0.
- **Correlation is weak, not absent:** pooled structure–churn correlation is ~0
  (−0.014) but rises to +0.20 within the single-file subset, and a few outlier
  tasks dominate the tail. Reported in §4.3 of the paper.
- **Small compact stratum:** 24 tasks; treat its statistics descriptively.
- **Single language family:** Python only.
- **An auditor should check:** the dialogue between the stratum split and the
  selection filter (§3), the F2P heuristic's false-negative rate, and whether the
  three-axis claim holds on a corpus the resource did not choose.

## 9. Ethical considerations

- No personal data. All material is public open-source code; attribution is
  preserved. No redistribution of competition-provided graphs or embeddings.
- The resource measures *structure*, not *people* or *models*; we make no claim
  that any model, tool, or repository is deficient.
